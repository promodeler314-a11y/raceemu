# design

[レースエミュレータ改良版の設計](../docs/webapp-design.md) の M3（UI の骨格）に対応する画面モック。

Claude Design のキャンバス上で編集できる形式（`.dc.html`）で置いてある。
1 ファイルが 1 アートボードで、`canvas.json` が配置と付箋を持つ。

| ファイル | 画面 |
| --- | --- |
| `Main.dc.html` | 設定パネル（未実行の状態） |
| `Summary.dc.html` | 実行とサマリ |
| `Compare.dc.html` | 比較（設定を列で並べる） |
| `Detail.dc.html` | 詳細（1 レースの推移とイベント） |
| `Error.dc.html` | エラー・中断と再開 |
| `Solve.dc.html` | 逆算・組み合わせ探索（M5・M6） |
| `Mobile.dc.html` | 設定（モバイル幅 390） |

`race-emulator-ui.html` はキャンバスとして公開するために生成したファイルであり、
編集の対象は上の 7 ファイルと `canvas.json` である。

## ブラウザで直接開くとき

`support.js` が、キャンバスの外で `.dc.html` を開いたときの実行時である。
各ファイルが `<script src="./support.js">` で読んでおり、
無いと `DCLogic is not defined` で止まって何も描かれない。

`design/*.dc.html` をブラウザで開けばそのまま動く。サーバも用意も要らない。
**外部に依存させないこと。** モックはビルド段を持たず `file://` で開くものなので、
`support.js` に CDN からの読み込みを足すと、手元で開けない場面ができる。
（書体だけは各 `.dc.html` が CDN から読んでいる。[#49](https://github.com/promodeler314-a11y/raceemu/issues/49)）

`support.js` はモックが実際に使っている機能だけを持つ。
`{{ 名前 }}` の差し込み、`onClick="{{ 関数 }}"` の結び付け、`<helmet>` の head への移動、
`DCLogic` の `state` / `setState` / `renderVals` である。
本家の実行時にある繰り返しや部品の読み込みは入っていない（詳しくはファイルの頭）。

**アートボードで動くのはライト／ダークの切替だけである。**
ヘッダのタブは `<span>` であって handler を持たない。1 つのタブが 1 つのアートボードなので、
面を移るのはキャンバスの上の移動であって、画面の中の操作ではない。
切替に指の形（`cursor: pointer`）を当てているのは `Main.dc.html` だけである（[ui-gap.md](../docs/ui-gap.md) 8 節）。

## 決めたこと

- ライト基調。影とカードではなく、罫線と余白で区切る。角丸 3px。
- 書体は IBM Plex Sans JP と IBM Plex Mono。数値は等幅で桁を揃える。
- 系列色は 速度 `#2a78d6` ／ 体力 `#eb6834` ／ 比較の 3 列目 `#1baf7a`。
  色覚のシミュレーションで隣接ペアの分離を確認済みで、`#1baf7a` は
  背景とのコントラストが 3:1 を下回るため直接ラベルを併記する。

## 設計から変えた点

- **速度と体力を二軸で重ねない。** 距離軸を共有した上下 2 段のパネルにする。
  尺度の違う 2 系列を 1 つの縦軸に載せると、両者の対応が恣意的になり、
  存在しない相関を読ませてしまう。
- **ヘッダに 設定／結果／比較／詳細 の区切りを置いた。**
  [webapp-design.md](../docs/webapp-design.md) 6.1 節は縦 1 カラムの積み上げだが、
  設定項目とグラフの量に対して 1 本のスクロールは長すぎる。
- **サマリのタイルに基準との差を出した。** 使い方の中心が
  「設定を少し変えて差を見る」ループであることを画面に出す試み。
- **ヘッダのタブに「探索」を追加した。** Error / Solve の追加に合わせて
  設定／結果／比較／詳細／探索 の 5 タブに揃えた（全画面共通）。
- **ライト／ダーク切替をヘッダに置いた。** 各画面のトークンをダーク値に
  差し替えるだけで成立するよう、色は CSS カスタムプロパティ経由にした。

## モバイル幅

`Mobile.dc.html` だけが 390px で、他は 1440px である。
狭い幅で**何を畳み、何を積み直すか**だけを持ち、各群の中身は `Main.dc.html` と同じなので繰り返さない。

- ヘッダは高さを固定せず折り返す。タブは減らさず、入り切らないぶんを横に送る。
  面の数を減らすと、狭い画面でだけ行けない面ができる。
- **実行バーは設定の列より先に置く。** 1440px では右の列の上端にあって常に見えているが、
  設定の列を上に積むと、実行にたどり着くまでに設定を全部通ることになる。
- ステータスの 5 列は 2 列に落とす。1 枠 62px では補正後の値が読めない。
  分割ボタン（脚質・やる気・バ場状態）は畳まない。選択肢が全部見えていることがこの形の値である。
- デバフ・実行オプション・相手の想定は、畳んだ見出しだけを既定にする。

実装（`apps/web`）は実行バーの位置がここと違う。差は [ui-gap.md](../docs/ui-gap.md) の 8 節にある。
