# 順位条件の判定を実戦に近づける

[順位条件の扱い](order-condition.md)で入れたフィールド軌跡モデルは、順位条件を「満たしている前提」から「実際に判定する」に変えた。
ところが判定を入れると、多くの順位条件つきスキルが「ほぼ発動しない」側に振れる。
無視すれば確実に発動し、判定すればほぼ発動しない。どちらも実戦の数字ではない。

本書では、まず「ほぼ発動しない」が何から来ているのかを実測で切り分け、次にどう組み替えれば実戦に近づくかを、同じ実測で比べて決める。
実測は `pnpm order-field` で再現できる（`packages/sim/src/field/order-cli.ts`）。

## 1. 測り方

東京 芝2400m、9 頭立て、200 試行。
自分の脚質を 4 通りに振り、代表的な順位条件が各フェーズで「1 フレームでも満たされた」試行の割合を数える。
これは、そのフェーズに発動区間を持つスキルの発動率の上限にあたる。
あわせて中盤末（2/3 地点）、終盤末（5/6 地点）、ゴールでの順位分布を出す。

自分のステータスは、チャンピオンズミーティングで普通に見る 1400-1100-1100-900-1100 を主に使う。
自分にも通常スキルを 8 つ持たせ、相手だけがスキルを持つ偏りを避けている。

## 2. 「ほぼ発動しない」の内訳

原因は一つではない。四つが重なっている。

### 2.1 相手が弱すぎて、自分が最初から最後まで先頭にいる

既定の相手は 1100-900-900-600-900 で固定されている（`defaultFieldProfile`）。
自分が 1400 なら、中盤には先頭に立ち、そのまま勝つ。

| 自分の脚質 | 中盤末に 1 位 | ゴールで 1 位 |
| --- | ---: | ---: |
| 先行 | 73 % | 100 % |
| 差し | 0 % | 100 % |
| 追込 | 0 % | 99 % |

その結果、「2 位以降」「順位率 40 以上」のような後方寄りの条件は、終盤とラストで 0 % になる。
[M6](m6-report.md) の 3 節で「逃げに後方寄りの条件は 0 %」と書いたのは正しいが、既定のままでは先行でも差しでも同じことが起きていた。
相手の強さは順位条件つきスキルの評価をそのまま左右する入力であり、既定値を自分から独立に固定しておくわけにはいかない。

### 2.2 相手が全員同一で、順位が塊の境目にしか出ない

既定の相手は 8 頭とも同じステータスでスキルを持たない。
同じ脚質の相手は数メートル以内に固まって走るので、自分は「塊の前」か「塊の後ろ」にしかいられない。

差し（1400）の中盤末の順位分布は、5 位が 100 % である。
逃げと先行の 4 頭には追いつけず、差しと追込の 4 頭は全員抜いている。
2 位から 4 位、6 位から 9 位が一度も出ない。
「3 位以内」「6 位以降」のような条件は、この量子化のせいで 0 % になる。

相手のステータスをばらつかせスキルを持たせると（3 節の B）、塊の中に入れるようになる。
ただしそれだけでは足りない。
先行（1400）の中盤末は 3 位 7 %、4 位 22 %、5 位 72 % で、依然として 1 位と 2 位、6 位以降が出ない。

### 2.3 相手が 1 頭ずつ独立に走っていて、隊列ができていない

フィールドの束は、相手 1 頭ぶんのレースを 8 回、別々に回して作っている（[M6](m6-report.md) 2 節）。
そのとき相手の位置取りは `APPROXIMATE`（固定区間でペースダウンするだけ）で、先頭に対して詰めたり離れたりはしない。
一方、全頭を同時に走らせる勝率の面（[M9](m9-report.md)）では、各頭が実在の先頭に対して位置取りする（`VIRTUAL`）。

同じ相手でも、この二つは違う隊列を作る。
独立に走らせた相手は、先頭との距離を保とうとしないので、同じ脚質どうしが縦に伸びず塊になる。
一緒に走らせた相手は、先行が先頭から 3 から 10 m、差しが 14 から 15 m、追込が 16 から 17 m の帯を保ちながら、帯の中で入れ替わる。

そして、自分の側にも同じ食い違いがある。
フィールドありの単騎モードでは、自分は `APPROXIMATE` で走る。
相手が先頭に対して位置取りしているのに自分だけが固定区間でペースダウンすると、自分だけ隊列から外れる。
実際、相手を一緒に走らせた束に対して自分を従来どおり走らせると、自分はゴール 9 位が逃げで 84 %、他の脚質で 95 % になる。
自分も同じ先頭に対して位置取りしなければ、束と噛み合わない。

この 84 % と 95 % は、4.2 節を入れる前に取った数字である。
いまは `calculator` がフィールドのあるときに `VIRTUAL` へ切り替えるので、自分だけを `APPROXIMATE` で走らせることができない。
食い違いを作る実験（`--exp mismatch`）は取り除いた。
3 節の A も同じ理由で、いま走らせると自分の位置取りだけが当時と違う。

### 2.4 出走前の同着

スタート直後、全頭が同じ位置にいる間は、誰から見ても「自分より前にいる相手」が 0 で順位が 1 になる。
出走の遅れは 0 から 0.1 秒なので数フレームの話だが、「序盤に 1 位」という条件はその数フレームで満たされてしまう。

出走前のフレームを判定から外すと、序盤の「1 位」は先行、差し、追込で 100 % から 41 から 46 % に下がる。
残る 4 割はスタートダッシュの混戦で一瞬先頭に立つぶんであり、これはゲームでも起きる。
出走前の同着だけが人工物である。

## 3. 組み替えの候補と、その効き

四つの作り方を同じ条件で比べた。
E は勝率の面と同じ駆動であり、本リポジトリの中では最も実戦に近い参照になる。

- **A 既定**：相手は 1100-900-900-600-900 で同一、スキル無し、1 頭ずつ独立に走らせる。自分は `APPROXIMATE`。
- **B 同格**：相手は自分と同格（各ステータスに σ80 のばらつき）、通常スキルを 11 個持つ。走らせ方は A と同じ。
- **C 一緒に走らせる**：B の相手を全頭同時に走らせて位置を記録し、自分もその束の先頭に対して位置取りする。
- **D 引き直し**：束の 1 本ごとに、脚質構成（8 通り）、強さ（σ120）、やる気、スキルの組を引き直す。走らせ方は C と同じ。
- **E 全頭同時**：B の相手と自分を同時に走らせる（勝率の面）。

先行（1400）の結果を抜く。

| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 3 位以内 | 中盤 | 100 % | 27 % | 33 % | 46 % | 44 % |
| 順位率 ≦ 50 | 終盤 | 100 % | 100 % | 80 % | 71 % | 86 % |
| 順位率 ≦ 50 | ラスト | 100 % | 100 % | 61 % | 65 % | 70 % |
| 順位率 > 50 | 中盤 | 0 % | 0 % | 22 % | 47 % | 16 % |
| 順位率 > 50 | 終盤 | 0 % | 0 % | 42 % | 46 % | 32 % |
| 2 位以降 | ラスト | 0 % | 100 % | 99 % | 95 % | 99 % |

| 中盤末の順位分布（1 位から 9 位、%） | | | | | | | | | |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| A 既定 | 73 | 17 | 11 | 0 | 1 | 0 | 0 | 0 | 0 |
| B 同格 | 0 | 0 | 7 | 22 | 72 | 0 | 0 | 0 | 0 |
| C 一緒に | 0 | 1 | 9 | 15 | 55 | 12 | 6 | 2 | 1 |
| D 引き直し | 1 | 3 | 15 | 21 | 27 | 16 | 13 | 4 | 3 |
| E 全頭同時 | 0 | 0 | 12 | 28 | 45 | 11 | 4 | 1 | 0 |

差し（1400）も同じ形になる。

| 条件 | フェーズ | A 既定 | B 同格 | C 一緒に | D 引き直し | E 全頭同時 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 3 位以内 | 終盤 | 52 % | 0 % | 2 % | 8 % | 2 % |
| 順位率 ≦ 50 | 中盤 | 100 % | 45 % | 27 % | 23 % | 39 % |
| 順位率 ≦ 50 | ラスト | 100 % | 34 % | 26 % | 57 % | 37 % |
| 順位率 > 50 | ラスト | 0 % | 79 % | 91 % | 81 % | 76 % |
| 1 位 | ラスト | 100 % | 0 % | 3 % | 10 % | 3 % |

読み取れることは三つある。

**A は全項目で外れている。** 前寄りの条件が 100 %、後ろ寄りの条件が 0 % で、E と反対側に振れている。
利用者が見ている「判定するとほぼ発動しない」は、この A で後ろ寄りの条件を持つスキルを見たときの姿である。

**B は分布の形が違う。** 同格にしてスキルを持たせても、順位は 3 位から 5 位に張り付き、1 位と 6 位以降が出ない。
2.2 節の量子化と 2.3 節の隊列の欠落が残っているためである。

**C は E と同じ形になる。** 先行の中盤末が 3 位から 7 位に広がり、差しが 5 位から 9 位に広がる。
条件ごとの数字も 10 ポイント前後の差に収まる。
残る差は、E では自分の走りが相手に影響するのに対し、C では影響しないぶんである。
D は C より広い。
これは相手の構成をばらつかせたぶん広がっているのであって、E より広いことをもって良し悪しは言えない。

## 4. 採用する判定アルゴリズム

順位条件つきスキルの発動率は、「その相手なら発動するか」ではなく「想定する相手の分布に対してどれだけの割合で発動するか」として出す。
フィールドは 1 つの相手ではなく相手の分布であり、束の 1 本ごとに相手を引き直す。
これが原則で、以下はその実装である。

### 4.1 束は相手同士を一緒に走らせて作る

**入れた。** `buildFieldBundle` を、相手 8 頭を `runMultiRace` で同時に走らせて位置を記録する形に変える。
相手は `VIRTUAL` で実在の先頭に対して位置取りする。
生成時間は 64 本で 3.1 秒（独立に走らせる現行は 2.4 秒）で、[M6](m6-report.md) 2 節の「指定だけを Worker に送ってキャッシュする」形はそのまま使える。

束には各フレームの先頭の位置と脚質も持たせる。
4.2 節で自分が読む。

### 4.2 自分も束の先頭に対して位置取りする

**入れた。** フィールドがあるとき、自分の位置取りは `VIRTUAL` にし、`paceMakerSource` に束の先頭を返す器を渡す。
位置取りの判定が読むのは先頭の `startPosition` と脚質だけなので、その 2 つを持つ小さな器で足りる（CLI の `runPaced` がそのまま実装の形である）。

これで単騎モードと勝率の面の位置取りが同じ規則になる。
[M8](m8-report.md) 2 節で「仮想先頭馬の入力口が無い」として画面から外していた `VIRTUAL` は、フィールドがあれば入力無しで使えるようになる。

### 4.3 相手の既定は自分と同格にし、ばらつかせる

**入れた。** `FieldProfile` に次を足した。

- **基準**：`matchSelf` を立てたら自分のステータスを写す。チャンピオンズミーティングの相手は自分と同じ育成をした個体である、という想定を既定にする。画面の「相手の想定」に「相手の強さ：自分と同じ / −100 / +100 / 固定」を置いた。
- **ばらつき**：各ステータスに σ（既定 100）の正規乱数を、束の本ごと相手ごとに乗せる。やる気も引く。やる気を σ と別に切る口は置いていない。片方だけ固定する意味が無いためである。
- **脚質構成**：固定の 1 通りではなく、9 頭立てなら 2-3-3-0、1-3-3-1、2-2-3-1、3-3-2-0 のような複数の構成から束の本ごとに引く。利用者が構成を固定したいときは 1 通りに絞れるようにする。
- **スキル**：脚質と距離ごとの典型セットから、束の本ごとに 5 から 8 個を引く。サーバのある版で個体を溜めている場合は、保存した個体（[サーバ側の設計](server-design.md)）から相手を引くほうが良い。個体の分布がそのまま相手の分布になる。

3 節の D がこの形である。
`defaultFieldProfile` の既定が D になり、`fixedFieldProfile` が引き直さない A の形を返す。
束の 1 本ごとの引き直しは鍵から決まるので、同じ指定なら何度作っても同じ束になる。
これを崩すと Worker ごとに違う束ができ、共通乱数によるペア比較が成り立たなくなる。

スキルは `packages/sim/src/field/opponent-skills.ts` の表から引く。
サーバのある版で個体を溜めている場合に個体から引く形は、まだ入れていない。

### 4.4 出走前は順位条件を判定しない

**入れた。** 自分の `delayTime` が 0 になるまで、順位と距離差の条件は偽とする。
相手どうしの同着は、先に出走した側が前になる（位置が動いた瞬間に前後がつく）ので、規則を足す必要は無い。

### 4.5 発動率には幅を添える

**入れた。** 相手の分布を変えれば発動率は動く。
「相手の強さ」を −100、0、+100 の 3 通りで走らせ、順位条件つきスキルの発動率を「下限 – 既定 – 上限」で出す。
3 通りぶん計算が増えるので、結果の面では既定だけを出し、幅は求めに応じて計算する。
スキル別の発動状況の表に「相手の強さで幅を見る」を置き、押したときだけ 3 通りを走らせて列を足す。
幅が 20 ポイント以上のものは色を変える。
CLI では `--opponent -100` のように相手の強さを振れる。

探索で幅の広いスキルに印を付ける（[逆算と組み合わせ探索の設計](solver-design.md) 4 節の感度分析にあたる）ところは、まだ入れていない。

### 4.6 自己整合（L3）は相手のスキルに自分の構成を混ぜる形で入れる

**入れた。** [順位条件の扱い](order-condition.md)の 6 節で「自分だけが強くなる歪み」として置いた L3 は、4.3 節の上に薄く載る。
探索の候補を評価するときに、束の相手のスキル構成に「いま評価している自分の構成」を一定の割合（3 割）で混ぜる。

作り直すのは 1 回だけである。貪欲で初期解が決まった時点で、その構成を相手に配って基準から測り直し、局所探索はその相手に対して回す。
局所探索の 1 巡ごとに作り直さないのは、巡どうしの短縮量が別々の相手に対する値になり、並べられなくなるからである。
束が変われば同じ構成でも結果が変わるので、それまでの評価はすべて捨てる。
捨てるのは基準と現在の構成だけで、局所探索はどのみち新しい構成を測るため、実測では 949 回が 952 回、521.4 秒が 522.7 秒にしかならなかった。

既定では切ってある。画面の「相手にも同じ構成を配る（自己整合）」、CLI では `--selfconsistent on` で入る。

**いまのところ、入れても答えは変わらない。**
東京 芝2400m、スペシャルウィーク、予算 600 pt で、入れても入れなくても同じ 4 つ（セイリオス、余勢を駆って、レースの真髄・心、華麗な足取り）が選ばれ、短縮量は 0.4040 秒と 0.4029 秒だった。
配るのが 5 個を相手の 3 割にだけなので、束の形がほとんど動かないためである。
割合を上げるか、相手の脚質に応じて配り分けるかで効き方は変わるはずだが、どちらが正しいかを決める材料がまだ無い。
収束の確認も含めて、6 節の実戦との比較が入るまで既定を切ったままにする。

## 5. 残る誤差

4 節を入れても、次は残る。

- **自分が相手に影響しない。** C と E の差がこれで、10 ポイント前後である。勝率の面（E）が正であり、単騎モードはその近似である。
- **ブロックとレーン。** 前が詰まって加速できない、外に出して抜くといった動きは無い。[M8](m8-report.md) 8 節のレーンに関わる 122 回ぶんはこのまま無視である。
- **スタート直後の混戦。** 出走前の同着を外しても、序盤の最初の数秒はほぼ横一線で、「序盤に 1 位」は 4 割の試行で一瞬満たされる。ゲームでも起きることだが、その一瞬に発動するスキルの効果は小さいので、発動率だけを見ると過大に見える。発動位置を併記して読み解けるようにする。

## 6. 何を実戦と比べるか

3 節の数字はモデルの中での整合であって、ゲームとの一致ではない。
合わせる相手は二つある。

- **順位の推移**：レースのリプレイから、中盤末（2/3 地点）と最終コーナーでの自分の順位を読む。脚質ごとに 20 レースずつ集めれば、3 節の順位分布と重ねられる。自分の順位だけでよく、相手の順位を全部読む必要は無い。
- **順位条件つきスキルの発動率**：レース結果のスキル発動ログから、順位条件つきスキルが発動したレースの割合を取る。同じ個体で 20 レースあれば 10 ポイント刻みの比較になる。

合わせる先は 4.3 節の σ とスキルの典型セットである。
モデルの式ではなく相手の分布を合わせるので、本家との突き合わせ（[M1](m1-report.md)）には触らない。

### 1、2、4 を入れたあとの順位分布

東京 芝2400m、相手は既定のまま（1100-900-900-600-900、スキル無し）、120 試行。
相手の中身は 3 の仕事なので、ここで動いたのは走らせ方だけである。

| 自分の脚質 | 中盤末の順位分布（1 位から 9 位、%） |
| --- | --- |
| 逃げ | 28 26 23 18 4 0 1 0 0 |
| 先行 | 0 3 19 33 31 11 3 2 0 |
| 差し | 0 0 0 6 17 19 16 24 18 |
| 追込 | 0 0 0 3 3 9 18 26 40 |

2.2 節の量子化が消えている。
どの脚質でも順位が 4 つ以上の値に散り、塊の境目に張り付かなくなった。
入れる前の既定（3 節の A）は、先行で 1 位 73 %、ゴール 1 位 100 % だった。

相手を同格にしてスキルを持たせる 3 が入るまでは、3 節の C とは並べられない。
C は相手が同格でスキルを持つ前提の数字である。

**相手が弱いぶんは、この時点では残っていた。** 自分が相手より 300 強ければ前に出るのが正しい挙動であって、
強い先行で後ろ寄りの条件がほとんど発動しないのは、判定の誤りではなく相手の想定の帰結である。
相手の強さを入力にする 3 は次の節で入った。

### 3 を入れたあとの順位分布

東京 芝2400m、自分 1400-1100-1100-900-1100、120 試行。
相手は既定（自分と同格、σ100、構成とやる気とスキルを束ごとに引き直す）である。
`pnpm order-field --trials 120 --exp redraw --level strong` で再現できる。

| 自分の脚質 | 中盤末（1 位から 9 位、%） | ゴール（同） |
| --- | --- | --- |
| 逃げ | 54 30 13 2 2 0 0 0 0 | 18 23 16 19 6 8 6 3 2 |
| 先行 | 0 3 8 25 25 18 13 5 3 | 8 8 11 9 10 10 13 20 12 |
| 差し | 0 0 0 1 4 16 23 24 33 | 6 8 9 13 8 14 16 18 8 |
| 追込 | 0 0 0 0 0 16 14 30 40 | 12 10 13 12 11 12 17 8 7 |

3 節の D とほぼ同じ形である（D は σ120 で測ったので、そのぶん広い）。
読むべきはゴールの列で、どの脚質でも 1 位が 1 割前後に落ち着いている。
9 頭立てで相手が自分と同格なら、これが正しい姿である。
相手を固定していたころは、どの脚質でもゴール 1 位がほぼ 100 % だった。

中盤末は脚質どおりに分かれたまま残る。
逃げは前、追込は後ろにいて、その中でばらつく。
順位条件つきスキルの発動率は、この分布に対する割合として出る。

### 発動率の幅（4.5 節）

同じ設定で、相手の強さだけを −100、0、+100 に振ったときの発動率。
自分は先行 1400-1100-1100-900-1100、1000 試行。

| スキル | 相手 −100 | 既定 | 相手 +100 | 幅 |
| --- | ---: | ---: | ---: | ---: |
| 抜け出し準備 | 73 % | 57 % | 35 % | 38 pt |
| 好位追走 | 69 % | 64 % | 58 % | 11 pt |
| 真骨頂 | 74 % | 79 % | 83 % | 8 pt |
| 末脚 | 92 % | 92 % | 92 % | 0 pt |
| コーナー巧者○ | 92 % | 92 % | 92 % | 0 pt |
| 先駆け | 0 % | 0 % | 0 % | 0 pt |
| 直線一気 | 0 % | 0 % | 0 % | 0 pt |

順位条件を持たないもの（末脚、コーナー巧者○）は動かない。
脚質が噛み合わないもの（先駆け、直線一気）は 0 % のまま動かない。
動くのは順位条件を持つものだけで、前寄りの条件（抜け出し準備）は相手が強いほど下がり、
後ろ寄りの条件（真骨頂）は相手が強いほど上がる。

抜け出し準備の 38 ポイントは、相手の想定を変えれば採否がひっくり返る大きさである。
1 つの数字だけを出していると、この振れが見えない。

## 8. 確率近似のうち、位置で決まるものを実際に計算する

本家は他馬を持たないので、追い抜きも前後のウマ娘も固定の確率で近似するしかなかった
（`packages/sim/src/skill/approximate.ts`）。
4 節でフィールドが入ったいま、**位置の比較だけで決まるものは確率を引く必要が無い。**
`packages/sim/src/field/conditions.ts` に置いた（[issue #74](https://github.com/promodeler314-a11y/raceemu/issues/74)）。

**フィールドが無いときは近似のままである。** 本家との突き合わせ
（`packages/sim/test/reference.test.ts`）はフィールドを渡さないので、ここは 1 ビットも動かない。
更新は近似と同じ 1 秒に 1 回で、状態の持ち方（続いた秒数を数える、回数を積む、その秒の変化を置く）も
そのままにしてある。条件の読み側（`skill/condition.ts` の `checkSpecialState`）を変えずに
中身だけを差し替えるためである。

### 8.1 置き換えた 12 型

| 定義数 | 型 | いままでの近似 | いまの決め方 |
| ---: | --- | --- | --- |
| 106 | `change_order_onetime` | 20 % で −1、20 % で +1 | 1 秒ぶんの順位の変化そのもの。追い抜けば負、追い抜かれれば正 |
| 102 | `is_overtake` | 脚質ごとに 5〜20 % で開始 | この 1 秒で追い抜いたか、近くの前の相手に差を詰めている |
| 35 | `overtake_target_time` | 15〜30 % で開始 | 近くの後ろの相手が差を詰めてきている秒数 |
| 27 | `infront_near_lane_time` | フェーズごとに 5〜20 % | すぐ前に相手がいる秒数 |
| 18 | `near_count` | フェーズごとの分布から抽選 | 前後「近く」にいる相手の数 |
| 14 | `behind_near_lane_time` | 15 % で開始 | すぐ後ろに相手がいる秒数 |
| 12 | `change_order_up_end_after` | 15 % で +1 | 終盤以降に追い抜いた回数 |
| 6 | `change_order_up_middle` | 5 % で +1 | 中盤に追い抜いた回数 |
| 4 | `is_surrounded` | 5 % で開始 | 前にも後ろにも近くに相手がいる秒数 |
| 2 | `overtake_target_no_order_up_time` | 80 % で開始 | 詰め寄られていて、まだ抜かれていない秒数 |
| 2 | `change_order_up_finalcorner_after` | 15 % で +1 | 最終コーナー以降に追い抜いた回数 |
| 2 | `near_infront_count` | 5 % で 1 | 前「近く」にいる相手の数 |

回数の区切り（中盤は中盤のあいだ、終盤以降は終盤から、最終コーナー以降はコーナーから）は
近似と同じにしてある。置き換えたのは「確率を引くのをやめて位置から決める」ところだけで、
区切りや読み側は動かしていない。
1 秒で 2 人抜いたときは 2 回と数える。条件が数えているのが「追い抜いた回数」だからである。

### 8.2 置き換えなかった型と、その理由

- **レーンが要るもの**：`blocked_side_continuetime`（79）、`blocked_front_continuetime`（8）、
  `is_move_lane`（8）、`blocked_front`（3）。前が詰まる・横を塞がれる・外に出すは、
  コース上の前後の位置だけでは決まらない。5 節で残した誤差そのものであり、
  [#55](https://github.com/promodeler314-a11y/raceemu/issues/55) につながる。
- **相手の状態が要るもの**：`temptation_opponent_count_behind`（2、後ろの相手の掛かり）、
  `is_other_character_activate_advantage_skill`（相手のスキル発動）。
  束が持っているのは位置だけで、相手の掛かりもスキル発動も記録していない。
- **`behind_near_lane_time_set1`（2）**：注記は「少し抜け出ていると」（煌星のヴォードヴィル）と読む。
  後ろとの差がある帯に入っていることを見ていると思われるが、**その帯が何メートルなのか
  手がかりが無い。** 「近く」の距離と違って、本家の近似の期待値にも注記にも当てられる
  相手がいない。帯を決めれば数字は出るが、それは勘で係数を置くことになるので、
  2 定義だけなら確率のままにしておくほうがましだと判断した。
  帯の手がかりが出たら位置から決められる。

### 8.3 「近く」を 1 バ身（2.5 m）と置いた

レーンを持たないので、「すぐ前」「すぐ後ろ」「近く」は前後の距離の差だけで決める。
**その境目が何メートルなのかは分かっていない。** 1 バ身の換算（[#52](https://github.com/promodeler314-a11y/raceemu/issues/52)）と同じ性質の未確認項目である。
`packages/sim/src/data/constants.ts` の `nearLaneMeters` に 1 か所だけ置き、
設定（`RaceSetting.nearLaneMeters`）で振れるようにしてある。

採った理由は二つで、**どちらもゲーム内での実測ではない。**

1. **本家の `near_count` の分布の期待値に合う。** 本家の近似は序盤 2.5 頭、中盤 1.0 頭、
   終盤 1.6 頭を置いている。東京 芝2400m・既定の相手（自分と同格、束ごとに引き直し）で
   1 秒ごとに数えると、こうなる。

   | 距離 | 序盤 | 中盤 | 終盤 | ラスト |
   | --- | ---: | ---: | ---: | ---: |
   | 2.5 m（1 バ身） | 2.8-3.4 | 0.9-1.3 | 0.9-1.5 | 1.3-1.7 |
   | 5 m | 4.1-4.6 | 1.8-2.3 | 1.8-2.9 | 2.7-3.2 |
   | 10 m | 5.2-6.0 | 3.3-4.1 | 3.6-5.4 | 4.8-5.5 |

   幅は脚質 4 通りの最小と最大である。中盤と終盤は 2.5 m がいちばん近く、
   5 m にするとどのフェーズもおよそ倍になる。
2. **注記の言葉づかいと揃う。** 「すぐ後ろのウマ娘との差が1バ身以内」（レッドエース）のように、
   注記は「すぐ前」「すぐ後ろ」を 1 バ身で書くことがある。別の条件型（`bashin_diff_behind`）の
   話ではあるが、同じ言葉を同じ距離で読むのは無理が無い。

**合わないところもある。** 本家の `near_infront_count` の近似は「前が空いている」を 95 % と置くが、
2.5 m で数えると 42〜48 % にしかならない。束の相手が本家の想定より詰まって走っているのか、
2.5 m が広すぎるのか、どちらとも決められない。
この型を使うのは 無二・無三 の 2 定義だけで、どちらも短距離限定である。

### 8.4 距離を振ったときの幅

`pnpm sensitivity --near 1.25,2.5,5 --trials 200`（東京芝2400、先行、スタミナ 1000、順位条件あり）。

| 近くの距離 | 平均タイム | 既定との差 |
| ---: | ---: | ---: |
| 1.25 m | 117.6215 秒 | +0.0291 ± 0.0070 秒 |
| 2.5 m（既定） | 117.6506 秒 | 0 |
| 5 m | 117.6850 秒 | −0.0344 ± 0.0080 秒 |

| スキル | 距離を見る | 1.25 m | 2.5 m | 5 m | 幅 | 幅 ÷ 誤差 |
| --- | :-: | ---: | ---: | ---: | ---: | ---: |
| ノンストップガール | ○ | 0.1639 | 0.2492 | 0.3309 | 0.1670 | 6.20 |
| どこ吹く風 | ○ | 0.0407 | 0.0523 | 0.0839 | 0.0432 | 4.99 |
| 勝利への執念 | ○ | 0.0669 | 0.0861 | 0.1000 | 0.0330 | 5.19 |
| ウマ好み | ○ | 0.0681 | 0.0718 | 0.0780 | 0.0098 | 0.60 |

距離を 2 倍にすると、前にウマ娘がいる条件の短縮量は 1.3 倍から 1.6 倍になる。

不確かさが確率から距離に移っただけで、消えたわけではない。
実測で当てるまでは、この 3 つの数字の幅の中で読む。

### 8.5 置き換えの前後で、発動率がどう動いたか

東京 芝2400m、9 頭、自分 1400-1100-1100-900-1100、200 試行、フィールドあり、発動抽選は固定。
スキルを 1 つだけ持たせて、1 回でも発動した試行の割合を数えた。

| スキル | 見ている型 | 先行 前 → 後 | 追込 前 → 後 |
| --- | --- | ---: | ---: |
| Guten Appetit♪ | `change_order_up_finalcorner_after` | 96.5 % → 6.0 % | 96.5 % → 34.5 % |
| 心、強し！ | `change_order_up_end_after` | 98.5 % → 28.5 % | 98.5 % → 59.5 % |
| 精神一到 | `change_order_onetime` | 100.0 % → 22.0 % | 100.0 % → 59.0 % |
| アガッてきた！ | `change_order_onetime` | 100.0 % → 64.0 % | 100.0 % → 58.5 % |
| 鋭気のアレグロ | `change_order_up_middle` | 99.5 % → 68.0 % | 100.0 % → 57.5 % |
| 勝利への執念 | `overtake_target_time` | 98.5 % → 84.5 % | 70.0 % → 15.5 % |
| どこ吹く風 | `is_surrounded` | 96.0 % → 88.5 % | 96.0 % → 49.0 % |
| Nemesis | `is_overtake` | 68.5 % → 55.0 % | 32.5 % → 19.0 % |
| ノンストップガール | `infront_near_lane_time` | 68.5 % → 98.0 % | 68.5 % → 81.0 % |
| お先に失礼っ！ | `behind_near_lane_time` | 78.0 % → 100.0 % | 78.0 % → 85.0 % |
| 鋼の意志（置き換えず） | `blocked_front_continuetime` | 90.5 % → 90.5 % | 91.5 % → 91.5 % |
| 末脚（対照） | 近似条件を見ない | 100.0 % → 100.0 % | 100.0 % → 100.0 % |

読み取れることは三つある。

**追い抜きを数える族は大きく下がる。** 毎秒 15 % で 1 回積む近似は、
終盤の 40 秒で期待 6 回になる。3 回以上という条件でもほぼ必ず満たされ、発動率は 96 % だった。
実際に順位の変化を数えると、終盤以降に 2 回追い抜くのは先行で 6 %、追込で 35 % である。
**ここは過大評価だった。**

**脚質で割れるようになった。** 近似は脚質を見ない（`change_order_up_*` はフェーズだけで決まる）ので、
先行でも追込でも同じ 96.5 % だった。いまは追い抜く側の追込が 34.5 %、
前に行ってしまう先行が 6.0 % と割れる。前後の条件では向きが逆になる。

**前後のウマ娘の族は上がる。** すぐ前・すぐ後ろに相手がいる時間は、
本家の近似（開始 5〜20 %、継続 30〜50 %）より長い。
束の相手が隊列を組んで走っているので、1 バ身以内に誰かがいる時間が実際に長い。
これが正しいかはゲームと突き合わせないと決められない。6 節の材料がここでも要る。

置き換えなかった型（鋼の意志）と対照（末脚）が動いていないので、
**動いたのは置き換えた型だけである**ことも確かめられる。

### 8.6 副作用として走りも変わる

`is_overtake`（追い抜きモード）は条件判定だけでなく、レーン移動にも効く（`applyMoveLane`）。
確率で決めていたころは脚質ごとの固定確率で外に出ていたが、いまは前の相手に詰めているときだけ外に出る。
そのぶん走る線が変わり、タイムも変わる。フィールドを渡したときだけの話である。

`packages/sim/test/field.test.ts` の「相対位置を見る条件が、脚質で発動を分ける」で、
追込のちょうど 0 が 60 試行に 1 本（1.7 %）になったのはこれである。
脚質で発動が分かれること自体は変わらないので、上限で見る形に直した。

### 8.7 感度分析との関係

**置き換えた型には `approximateRateScale` の倍率が効かない。** 確率を引かなくなったからである。
そのぶん倍率の軸で動く量は小さくなった（同じ設定・200 試行で、平均タイムの幅が
0.2865 秒。置き換える前は 600 試行で 0.68 秒だった）。
ノンストップガールの短縮量の幅は、倍率の軸では 0.32 秒から 0.0255 秒に落ち、
代わりに距離の軸で 0.1670 秒になる。
**不確かさが「確率をどう置くか」から「近くを何メートルと置くか」に移った。**
`pnpm sensitivity` は `--near` でそちらの軸を振れる（[逆算と組み合わせ探索の設計](solver-design.md) 4.1 節）。

### 8.8 分類の印

再現度の分類（`packages/sim/src/skill/classify.ts`）では、**置き換えた型も △（近似）のままである。**
確率を引かなくなっても相手は作り物の束であり、「近く」の距離も読み取りだからである。
変わるのは理由の文で、フィールドを渡したときだけ
「確率ではなく相手の位置から判定している」に切り替わる。
`packages/sim/test/skill-fidelity.test.ts` がこの切り替わりを見張っている。
