# 順位条件の判定を実戦に近づける

[順位条件の扱い](order-condition.md)で入れたフィールド軌跡モデルは、順位条件を「満たしている前提」から「実際に判定する」に変えた。
ところが判定を入れると、多くの順位条件つきスキルが「ほぼ発動しない」側に振れる。
無視すれば確実に発動し、判定すればほぼ発動しない。どちらも実戦の数字ではない。

本書では、まず「ほぼ発動しない」が何から来ているのかを実測で切り分け、次にどう組み替えれば実戦に近づくかを、同じ実測で比べて決める。
実測は `pnpm order-field` で再現できる（`packages/sim/src/field/order-cli.ts`）。

## 1. 測り方

東京 芝2400m、9 頭立て、200 試行。
自分の脚質を 4 通りに振り、代表的な順位条件が各フェーズで「1 フレームでも満たされた」試行の割合を数える。
これは、そのフェーズに発動区間を持つスキルの発動率の上限にあたる。
あわせて中盤末（2/3 地点）、終盤末（5/6 地点）、ゴールでの順位分布を出す。

自分のステータスは、チャンピオンズミーティングで普通に見る 1400-1100-1100-900-1100 を主に使う。
自分にも通常スキルを 8 つ持たせ、相手だけがスキルを持つ偏りを避けている。

## 2. 「ほぼ発動しない」の内訳

原因は一つではない。四つが重なっている。

### 2.1 相手が弱すぎて、自分が最初から最後まで先頭にいる

既定の相手は 1100-900-900-600-900 で固定されている（`defaultFieldProfile`）。
自分が 1400 なら、中盤には先頭に立ち、そのまま勝つ。

| 自分の脚質 | 中盤末に 1 位 | ゴールで 1 位 |
| --- | ---: | ---: |
| 先行 | 73 % | 100 % |
| 差し | 0 % | 100 % |
| 追込 | 0 % | 99 % |

その結果、「2 位以降」「順位率 40 以上」のような後方寄りの条件は、終盤とラストで 0 % になる。
[M6](m6-report.md) の 3 節で「逃げに後方寄りの条件は 0 %」と書いたのは正しいが、既定のままでは先行でも差しでも同じことが起きていた。
相手の強さは順位条件つきスキルの評価をそのまま左右する入力であり、既定値を自分から独立に固定しておくわけにはいかない。

### 2.2 相手が全員同一で、順位が塊の境目にしか出ない

既定の相手は 8 頭とも同じステータスでスキルを持たない。
同じ脚質の相手は数メートル以内に固まって走るので、自分は「塊の前」か「塊の後ろ」にしかいられない。

差し（1400）の中盤末の順位分布は、5 位が 100 % である。
逃げと先行の 4 頭には追いつけず、差しと追込の 4 頭は全員抜いている。
2 位から 4 位、6 位から 9 位が一度も出ない。
「3 位以内」「6 位以降」のような条件は、この量子化のせいで 0 % になる。

相手のステータスをばらつかせスキルを持たせると（3 節の B）、塊の中に入れるようになる。
ただしそれだけでは足りない。
先行（1400）の中盤末は 3 位 7 %、4 位 22 %、5 位 72 % で、依然として 1 位と 2 位、6 位以降が出ない。

### 2.3 相手が 1 頭ずつ独立に走っていて、隊列ができていない

フィールドの束は、相手 1 頭ぶんのレースを 8 回、別々に回して作っている（[M6](m6-report.md) 2 節）。
そのとき相手の位置取りは `APPROXIMATE`（固定区間でペースダウンするだけ）で、先頭に対して詰めたり離れたりはしない。
一方、全頭を同時に走らせる勝率の面（[M9](m9-report.md)）では、各頭が実在の先頭に対して位置取りする（`VIRTUAL`）。

同じ相手でも、この二つは違う隊列を作る。
独立に走らせた相手は、先頭との距離を保とうとしないので、同じ脚質どうしが縦に伸びず塊になる。
一緒に走らせた相手は、先行が先頭から 3 から 10 m、差しが 14 から 15 m、追込が 16 から 17 m の帯を保ちながら、帯の中で入れ替わる。

そして、自分の側にも同じ食い違いがある。
フィールドありの単騎モードでは、自分は `APPROXIMATE` で走る。
相手が先頭に対して位置取りしているのに自分だけが固定区間でペースダウンすると、自分だけ隊列から外れる。
実際、相手を一緒に走らせた束に対して自分を従来どおり走らせると、自分はゴール 9 位が逃げで 84 %、他の脚質で 95 % になる（`pnpm order-field --exp mismatch`）。
自分も同じ先頭に対して位置取りしなければ、束と噛み合わない。

### 2.4 出走前の同着

スタート直後、全頭が同じ位置にいる間は、誰から見ても「自分より前にいる相手」が 0 で順位が 1 になる。
出走の遅れは 0 から 0.1 秒なので数フレームの話だが、「序盤に 1 位」という条件はその数フレームで満たされてしまう。

出走前のフレームを判定から外すと、序盤の「1 位」は先行、差し、追込で 100 % から 41 から 46 % に下がる。
残る 4 割はスタートダッシュの混戦で一瞬先頭に立つぶんであり、これはゲームでも起きる。
出走前の同着だけが人工物である。

## 3. 組み替えの候補と、その効き

四つの作り方を同じ条件で比べた。
E は勝率の面と同じ駆動であり、本リポジトリの中では最も実戦に近い参照になる。

- **A 既定**：相手は 1100-900-900-600-900 で同一、スキル無し、1 頭ずつ独立に走らせる。自分は `APPROXIMATE`。
- **B 同格**：相手は自分と同格（各ステータスに σ80 のばらつき）、通常スキルを 11 個持つ。走らせ方は A と同じ。
- **C 一緒に走らせる**：B の相手を全頭同時に走らせて位置を記録し、自分もその束の先頭に対して位置取りする。
- **D 引き直し**：束の 1 本ごとに、脚質構成（8 通り）、強さ（σ120）、やる気、スキルの組を引き直す。走らせ方は C と同じ。
- **E 全頭同時**：B の相手と自分を同時に走らせる（勝率の面）。

先行（1400）の結果を抜く。

| 条件 | フェーズ | A 既定 | B 同格 | C 一緒に | D 引き直し | E 全頭同時 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 3 位以内 | 中盤 | 100 % | 27 % | 33 % | 46 % | 44 % |
| 順位率 ≦ 50 | 終盤 | 100 % | 100 % | 80 % | 71 % | 86 % |
| 順位率 ≦ 50 | ラスト | 100 % | 100 % | 61 % | 65 % | 70 % |
| 順位率 > 50 | 中盤 | 0 % | 0 % | 22 % | 47 % | 16 % |
| 順位率 > 50 | 終盤 | 0 % | 0 % | 42 % | 46 % | 32 % |
| 2 位以降 | ラスト | 0 % | 100 % | 99 % | 95 % | 99 % |

| 中盤末の順位分布（1 位から 9 位、%） | | | | | | | | | |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| A 既定 | 73 | 17 | 11 | 0 | 1 | 0 | 0 | 0 | 0 |
| B 同格 | 0 | 0 | 7 | 22 | 72 | 0 | 0 | 0 | 0 |
| C 一緒に | 0 | 1 | 9 | 15 | 55 | 12 | 6 | 2 | 1 |
| D 引き直し | 1 | 3 | 15 | 21 | 27 | 16 | 13 | 4 | 3 |
| E 全頭同時 | 0 | 0 | 12 | 28 | 45 | 11 | 4 | 1 | 0 |

差し（1400）も同じ形になる。

| 条件 | フェーズ | A 既定 | B 同格 | C 一緒に | D 引き直し | E 全頭同時 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 3 位以内 | 終盤 | 52 % | 0 % | 2 % | 8 % | 2 % |
| 順位率 ≦ 50 | 中盤 | 100 % | 45 % | 27 % | 23 % | 39 % |
| 順位率 ≦ 50 | ラスト | 100 % | 34 % | 26 % | 57 % | 37 % |
| 順位率 > 50 | ラスト | 0 % | 79 % | 91 % | 81 % | 76 % |
| 1 位 | ラスト | 100 % | 0 % | 3 % | 10 % | 3 % |

読み取れることは三つある。

**A は全項目で外れている。** 前寄りの条件が 100 %、後ろ寄りの条件が 0 % で、E と反対側に振れている。
利用者が見ている「判定するとほぼ発動しない」は、この A で後ろ寄りの条件を持つスキルを見たときの姿である。

**B は分布の形が違う。** 同格にしてスキルを持たせても、順位は 3 位から 5 位に張り付き、1 位と 6 位以降が出ない。
2.2 節の量子化と 2.3 節の隊列の欠落が残っているためである。

**C は E と同じ形になる。** 先行の中盤末が 3 位から 7 位に広がり、差しが 5 位から 9 位に広がる。
条件ごとの数字も 10 ポイント前後の差に収まる。
残る差は、E では自分の走りが相手に影響するのに対し、C では影響しないぶんである。
D は C より広い。
これは相手の構成をばらつかせたぶん広がっているのであって、E より広いことをもって良し悪しは言えない。

## 4. 採用する判定アルゴリズム

順位条件つきスキルの発動率は、「その相手なら発動するか」ではなく「想定する相手の分布に対してどれだけの割合で発動するか」として出す。
フィールドは 1 つの相手ではなく相手の分布であり、束の 1 本ごとに相手を引き直す。
これが原則で、以下はその実装である。

### 4.1 束は相手同士を一緒に走らせて作る

`buildFieldBundle` を、相手 8 頭を `runMultiRace` で同時に走らせて位置を記録する形に変える。
相手は `VIRTUAL` で実在の先頭に対して位置取りする。
生成時間は 64 本で 3.1 秒（独立に走らせる現行は 2.4 秒）で、[M6](m6-report.md) 2 節の「指定だけを Worker に送ってキャッシュする」形はそのまま使える。

束には各フレームの先頭の位置と脚質も持たせる。
4.2 節で自分が読む。

### 4.2 自分も束の先頭に対して位置取りする

フィールドがあるとき、自分の位置取りは `VIRTUAL` にし、`paceMakerSource` に束の先頭を返す器を渡す。
位置取りの判定が読むのは先頭の `startPosition` と脚質だけなので、その 2 つを持つ小さな器で足りる（CLI の `runPaced` がそのまま実装の形である）。

これで単騎モードと勝率の面の位置取りが同じ規則になる。
[M8](m8-report.md) 2 節で「仮想先頭馬の入力口が無い」として画面から外していた `VIRTUAL` は、フィールドがあれば入力無しで使えるようになる。

### 4.3 相手の既定は自分と同格にし、ばらつかせる

`FieldProfile` に次を足す。

- **基準**：`uma` を省略したら自分のステータスを写す。チャンピオンズミーティングの相手は自分と同じ育成をした個体である、という想定を既定にする。画面には「相手の強さ：自分と同じ / −100 / +100」の 3 段と、数値の直接入力を置く。
- **ばらつき**：各ステータスに σ（既定 100）の正規乱数を、束の本ごと相手ごとに乗せる。やる気も引く。
- **脚質構成**：固定の 1 通りではなく、9 頭立てなら 2-3-3-0、1-3-3-1、2-2-3-1、3-3-2-0 のような複数の構成から束の本ごとに引く。利用者が構成を固定したいときは 1 通りに絞れるようにする。
- **スキル**：脚質と距離ごとの典型セットから、束の本ごとに 5 から 8 個を引く。サーバのある版で個体を溜めている場合は、保存した個体（[サーバ側の設計](server-design.md)）から相手を引くほうが良い。個体の分布がそのまま相手の分布になる。

3 節の D がこの形である。

### 4.4 出走前は順位条件を判定しない

自分の `delayTime` が 0 になるまで、順位と距離差の条件は偽とする。
相手どうしの同着は、先に出走した側が前になる（位置が動いた瞬間に前後がつく）ので、規則を足す必要は無い。

### 4.5 発動率には幅を添える

相手の分布を変えれば発動率は動く。
「相手の強さ」を −100、0、+100 の 3 通りで走らせ、順位条件つきスキルの発動率を「下限 – 既定 – 上限」で出す。
3 通りぶん計算が増えるので、結果の面では既定だけを出し、幅は求めに応じて計算する。
探索では、幅の広いスキルに印を付ける（[逆算と組み合わせ探索の設計](solver-design.md) 4 節の感度分析にあたる）。

### 4.6 自己整合（L3）は相手のスキルに自分の構成を混ぜる形で入れる

[順位条件の扱い](order-condition.md)の 6 節で「自分だけが強くなる歪み」として置いた L3 は、4.3 節の上に薄く載る。
探索の候補を評価するときに、束の相手のスキル構成に「いま評価している自分の構成」を一定の割合で混ぜる。
束を毎回作り直す必要はなく、探索の各段階（予算の刻み）で 1 回作り直せば足りる。
収束の確認は実装後に回す。

## 5. 残る誤差

4 節を入れても、次は残る。

- **自分が相手に影響しない。** C と E の差がこれで、10 ポイント前後である。勝率の面（E）が正であり、単騎モードはその近似である。
- **ブロックとレーン。** 前が詰まって加速できない、外に出して抜くといった動きは無い。[M8](m8-report.md) 8 節のレーンに関わる 122 回ぶんはこのまま無視である。
- **スタート直後の混戦。** 出走前の同着を外しても、序盤の最初の数秒はほぼ横一線で、「序盤に 1 位」は 4 割の試行で一瞬満たされる。ゲームでも起きることだが、その一瞬に発動するスキルの効果は小さいので、発動率だけを見ると過大に見える。発動位置を併記して読み解けるようにする。

## 6. 何を実戦と比べるか

3 節の数字はモデルの中での整合であって、ゲームとの一致ではない。
合わせる相手は二つある。

- **順位の推移**：レースのリプレイから、中盤末（2/3 地点）と最終コーナーでの自分の順位を読む。脚質ごとに 20 レースずつ集めれば、3 節の順位分布と重ねられる。自分の順位だけでよく、相手の順位を全部読む必要は無い。
- **順位条件つきスキルの発動率**：レース結果のスキル発動ログから、順位条件つきスキルが発動したレースの割合を取る。同じ個体で 20 レースあれば 10 ポイント刻みの比較になる。

合わせる先は 4.3 節の σ とスキルの典型セットである。
モデルの式ではなく相手の分布を合わせるので、本家との突き合わせ（[M1](m1-report.md)）には触らない。
