# モックと実装のズレ

[UI のモック](../design/README.md)と、動いている `apps/web` を突き合わせた記録である。

**モックを正とする。**
6 面ぶんが `design/*.dc.html` に入っており、Claude Design 側で編集されたものが正である。

対応の欄は次の三つを使う。

- **実装を寄せる**：モックが正しく、コードを直す。
- **モックを直す**：実装の判断のほうが妥当で、モックの側を後で調整する。
- **未決**：どちらが良いか決めきれていない。

## 3. 設定（`Main.dc.html`）

| 項目 | モック | 実装 | 対応 |
| --- | --- | --- | --- |
| 群の畳み込み | ウマ娘／コース／所持スキル／受けるデバフ／実行オプション を開閉でき、畳んだときは要約を横に出す | 常に開いたパネル | 実装を寄せる |
| 脚質・やる気・バ場状態 | 分割ボタン（選択肢が全部見える） | 済み |
| ステータス | 入力の下に補正後の値を出す | 済み |
| コース形状 | 高低差とコーナーの小さな図 | 済み |
| スキル | 名前・Lv・近似の印を持つチップ、検索して追加 | 概ね寄っている |
| キャラ（固有と進化） | **モックに無い** | 入れた | モックを直す |
| 実行オプション | 分割ボタン（2 択） | **`<select>` のまま。モックを直す** |
| 空状態 | **プリセット 3 つと「本家エミュレータの設定を読み込む」** | プリセットは入れた。読み込みは未（8 節） | 一部済み |
| 所要時間の見積もり | 実行前に「8 スレッドで約 1.4 秒の見込み」 | 実行後の実測のみ | 実装を寄せる |

空状態とプリセットは、初めて開いた人が最初に当たる面である。

**キャラの入力はモックに無い。**
モックは所持スキルを 1 つの検索欄で済ませており、固有をどう取るかが描かれていない。
本家は固有と進化をキャラの側から選ばせ、一覧には出さない。
移植版は一覧に全レア度を混ぜていたため、誰の固有なのかが画面に出ず、別のキャラの固有を
同時に持てた。本家に合わせたので、ここはモックの側を直す。

**実行オプションは分割ボタンにしない。**
モックは 2 択（有効／無効、抽選／100% 固定）に簡略化しているが、実装はスキル発動率が 3 択、
ランダム発動区間が 6 択、ポジションキープが 3 択ある。
寄せると選択肢が減るので、ここはモックの側を直す。

補正後の値は「適性」ではない。
効いているのはやる気、コースの得意ステータス（`courseSetStatus`）、バ場、脚質適性である。
どれが効いたかまでは出していない。ここで見たいのは「入力した値と違う」ことだからである。

## 5. 比較・詳細・エラー

`Detail.dc.html` の**イベント一覧を入れた**。
フレーム列は前から持っていたのに、画面には図しか出していなかった。
図は「どう動いたか」は見せるが「なぜそこで変わったのか」は見せない。
速度が落ちた場所にコーナーがあったのか、スキルが切れたのか、掛かったのかは、
時刻順に並べて初めて読める。

拾っているのはスキルの発動、フェーズ境界、コーナー進入、状態の立ち上がりと終わり
（掛かり・位置取り調整・持久力温存・先頭争い・追い比べ・下り坂加速・スパートなど）、
それにゴールである。
状態は立ち上がりだけを拾う。毎フレーム真であり続けるものをそのまま並べると、
数百行のうち大半が同じ行になる。

詳細には、どの試行を開いているかと前後への移動も足した。
「試行 0」とだけ出ていても、それが速いほうなのか遅いほうなのかが分からない。
分布のどこにいるか（速いほうから何 %）を併せて出している。

比較は作り直した。
行を結果・ステータス・コース・スキルの 4 群に分け、基準の列を選べるようにし、
差のある項目だけに畳めるようにした。
12 行を平坦に並べていたときは、どこが違うのかを目で探す必要があった。

**分布の重ね合わせのために、スナップショットに畳んだヒストグラムを持たせた。**
毎試行の値をそのまま持つと、試行が最大 20 万回あるので 1 件で 1.6 MB になる。
60 のビンに畳めば数百バイトで済み、図に描くぶんには元の値と区別が付かない。
古いスナップショットには無いので、その列は重ね合わせに出ない。

平均タイムの差には 95% の区間を添えた。
ただし**これは列どうしを別々に平均して求めたもので、探索の画面で使っている
試行ごとに引き算した区間より広い**。
スナップショットは別々に走らせたものなので、試行を対応付けられない。
画面にもそう書いてある。

`Error.dc.html` のうち、失敗と知らせの帯は[M8](m8-report.md)で入れてある。
今回足したのは**中断したときに途中までの結果を捨てないこと**である。
長く走らせたあとに手を止めた人が、最初からやり直すことになっていた。

`Error.dc.html` は新しい面である。
実装には[失敗の見せ方](m8-report.md)（上端の帯と描画の受け皿）があるが、
モックは 1 枚の面として設計している。突き合わせは骨格を入れてからにする。

## 6. 図の色

| 系列 | 割り当て |
| --- | --- |
| 速度 | `#2a78d6`（青） |
| 目標速度 | 文脈色の破線 |
| 体力 | `#eb6834`（橙） |
| 比較の 3 列目 | `#1baf7a`（アクア） |

モックの割り当てに寄せた。
目標速度は速度と同じ量の参照線であって別の系列ではないので、カテゴリ色を 1 枠使うのは割に合わない。
`#1baf7a` は明色面でのコントラストが 3:1 を下回るため、主要な系列に充てるより使用頻度の低い枠に回している。

## 7. 直す順序

1. ~~見た目の土台~~ 済み。色を `@theme` のトークンに移し、書体・角丸・罫線を当てた。`dark:` は消えて、ダークはトークンの差し替えだけになった。
2. ~~画面の骨格~~ 済み。ヘッダのタブ（モックの 5 つに勝率を足した 6 つ）、左の要約レール、実行バー、フッタ。
3. ~~設定の空状態とプリセット~~ 済み。ただし「本家エミュレータの設定を読み込む」は入れていない（8 節）。
4. ~~探索の面~~ 済み。実行の内訳をボタンの横に出し、達成率の表といまの設定値を対応付け、警告を帯にした。
5. ~~設定の入力の形~~ 済み。分割ボタン、補正後の値、コース形状の図。実行オプションは上のとおりモックを直す。
6. ~~比較と詳細~~ 済み。
7. ~~エラーの面と図の色~~ 済み。図の色はモックの割り当てに変えた。目標速度は速度と同じ量の
   参照線なので、カテゴリ色を使わず破線の文脈色にし、空いた橙を体力に回した。

**モックに対する寄せはここで一巡した。** 残りは 8 節の積み残しである。

## 8. 積み残し

- **`design/support.js` がリポジトリに無い。** 各 `.dc.html` が `./support.js` を読み込んでおり、
  無いと `DCLogic is not defined` になる。静的な描画はできるので参照には足りるが、
  タブの切替やダークの切替といった動きは確かめられない。
- **`race-emulator-ui.html` が 4 画面のときのまま。** Error と Solve を含んでいない。
  キャンバスとして公開し直すときに再生成が要る（`design/README.md` に注記あり）。
- **中断からの再開を実装していない。** モックの「続きから再開する」である。
  途中までの結果は残すようにし、押す前の所要時間の見積もりも出すようにしたが、再開はできない。
  塊は順不同で終わるため、埋まっていない試行番号が飛び飛びに残る。
  「N 件目から」という 1 つの位置では表せず、区間の集合を持ち回る必要がある。
  作れないわけではないが、`WorkerPool` の受け渡しを変える話になるので分けた。
- **「本家エミュレータの設定を読み込む」は入れた。** 形式が分かったので実装した
  （[M10 の後の方針](roadmap.md)の 3.5 節、`apps/web/src/transfer.ts`）。
  設定の面の「本家と設定をやり取りする」で読み書きする。
  モックの空状態にあるリンクからは繋いでいない。
- **モバイル幅は描かれていない。** 実装は幅 390 で横あふれが無いことを `pnpm e2e` で見ているだけである。
  骨格を入れるにあたり、狭い幅ではヘッダを折り返し、左の列を全幅にして縦に積むようにした。
  モックに無い判断なので、描かれたら見直す。
- **書体を CDN から読んでいる。** IBM Plex Sans JP は日本語を含むぶん大きく、同梱するとバンドルの
  上限に当たる。取れなければ代替の書体で動くようにしてあり、`pnpm e2e` は読み込みの失敗を
  アプリの誤りとして数えない。自前ホストで外部への依存を無くしたい場合は、ここを見直すことになる。
