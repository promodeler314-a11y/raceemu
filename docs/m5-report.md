# M5 の結果

[改良版の設計](webapp-design.md)の M5、逆算ができた。
[逆算と組み合わせ探索の設計](solver-design.md)の 2.3 節で「実装時に検査する」と決めた単調性を先に測り、その結果で探し方を決めている。

## 1. 単調性の検査

1 試行の中でスタミナを 200 から 1600 まで 10 刻みで動かし、目標の達成が単調に変わるかを調べた。
乱数はストリームごとに分けてあるので、試行番号が同じならスタミナ以外の出目は変わらない。
達成の並びは 0 が続いてから 1 が続く形になるはずであり、そうならない箇所が反転である。

9 通りの設定（コース 4 種、脚質 4 種、賢さと根性を振った 2 種）について 60 試行ずつ調べた。

| 目標 | 反転を含む試行 | 反転の最大幅 |
| --- | ---: | ---: |
| 最大スパート | 540 試行中 0 件 | 0 |
| 完走 | 540 試行中 253 件（47 パーセント） | 350 |

**結果は目標によって割れた。**
最大スパートは完全に単調で、反転が 1 件も出ない。
完走は半数近い試行で反転する。

## 2. 完走が単調でない理由

反転の形を見ると、原因がはっきりする。
スタミナを 20 刻みで動かしたときの、ある試行の達成の並びである。

```
完走:         0000000000000000 0111111111111 00000 1111111111111111111
最大スパート: 0000000000000000 0000000000000 01111 1111111111111111111
```

**完走が一度 0 に戻る帯は、最大スパートが立ち上がる位置とぴったり重なる。**

スタミナがまだ足りないうちは、ラストスパートの計算が控えめな速度を選ぶので、体力を余らせてゴールする。
最大スパートに手が届く量になると、計算は最高速度で押し切る計画に切り替える。
切り替わった直後は消費が供給をわずかに上回り、ゴール時の体力が負になる。
さらにスタミナが増えると再び足りるようになり、完走に戻る。

つまり**スパートするかどうかという離散的な判断が、一時的に完走を悪化させる**。
モデルの誤りではなく、モデルがそう振る舞う。

## 3. 探し方の決定

反転があると二分探索は成り立たない。
どれだけ外れるかを、二分探索と全走査の答えを 200 試行で突き合わせて測った。

| 目標 | 答えが違う試行 | 平均のずれ | 最大のずれ |
| --- | ---: | ---: | ---: |
| 最大スパート | 0 / 200 | 0 | 0 |
| 完走 | 42 / 200（21 パーセント） | 345 | 360 |

そこで、目標ごとに探し方を変える。

- **最大スパート**：二分探索。1 試行あたり 12.2 本のレースで済む。
- **完走と残り体力**：全走査。1 試行あたり 60 本ほどかかる（達成した時点で止まるので、範囲の全点を走るわけではない）。

二分探索には、見つけた境界の左を数点だけ調べる保険も入れてある。
ただしこれは境界から離れた反転を捕まえられないので、保証ではない。
実際、完走を二分探索で解くと保険はほとんど作動しないまま 2 割の試行で誤った答えを返す。
だから保険ではなく、目標ごとの選択で分けている。

## 4. 実装

```
packages/solver/src/
  target.ts             逆算の対象と目標の定義
  critical.ts           試行ごとの臨界値、達成率ごとの必要値
  monotonicity.ts       単調性の検査
  monotonicity-check.ts 検査を並べて表にする（pnpm monotonicity）
```

並列実行にも載せた。
Worker への依頼を種類で分け、プールの配り方は共通のまま `runCritical` を足している。
Worker が求めた臨界値が単一スレッドの結果と 1 件ずつ一致することをテストで確かめた。

## 5. 出力

達成率ごとの必要値を表にし、臨界値の分布をヒストグラムで出す。

素朴に「達成率 80 パーセントの必要スタミナ」を測るだけなら、スタミナを二分探索して各点で達成率を数える方法もある。
しかしそれでは 1 つの数字しか得られない。
試行ごとの臨界値を集める方式なら、**同じ計算量で達成率の曲線がまるごと手に入る**。

実際の出力（東京芝2400、先行、スキル 2 つ、300 試行）は次のようになる。

| 達成率 | 必要なスタミナ |
| ---: | ---: |
| 50 % | 590 |
| 80 % | 660 |
| 90 % | 750 |
| 99 % | 890 |

分布の形も見えるので、二山になっている（掛かるかどうかで結果が二分されている、など）ことに気付ける。

## 6. 積み残し

- **完走の逆算は重い**：1 試行あたり 60 本なので、500 試行で 3 万本になる。並列で数十秒かかる。刻みを粗くして絞り込む案はあるが、反転の幅が最大 350 あるため、粗い走査では達成する帯を跨いでしまう。刻みを利用者に選ばせるかは未決である。
- **逆算の対象**：スピードやパワーも選べるようにしてあるが、単調性を検査したのはスタミナだけである。他のステータスは検査していない。
- **発動率の固定**：M4 の積み残しのまま。逆算では乱数の幅を狭めたい場面があるので、次に入れる。
